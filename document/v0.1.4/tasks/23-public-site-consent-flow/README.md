# 23. Public site and consent flow

## 目的

公開サイトを、撮影に協力する現場、データを購入する研究開発者、データの取扱いを確認する人の三つの入口に整理する。あわせて、撮影前の合意から提供前の現場承認までを、現場が理解し実行できる通常フローとして示す。

## 公開サイトの構成

- `/`: RootLensの課題認識と事業モデルを説明し、三つの入口へ案内するLP
- `/contribute`: 現場が撮影開始前に理解する内容、役割、撮影協力費の考え方
- `/buy`: 研究開発者向けの収集構成、提供形式、データ来歴
- `/data-policy`: 事前合意、提供前承認、証跡の対応関係

## 同意・承認の通常フロー

1. RootLensと撮影先が現場合意書を締結する。
2. 撮影機材を装着する本人が、撮影参加に関する同意書へ署名する。
3. 現場監督者が撮影データを確認し、提供を認めるデータだけを承認してアップロードする。
4. RootLensは承認済みデータに必要なプライバシー処理を行い、合意した確認期間を経て販売先へ提供する。
5. 提供用データから、撮影先の合意、撮影者の同意、現場監督者の承認をたどれる状態を維持する。

## 承認者の認証方針

現場監督者の実在性を、SNS事業者や本人確認サービスへ重ねて証明すること自体は目的にしない。誰が撮影先を代表して承認できるかは、現場合意の際に撮影先が指定する。

- RootLensが撮影先ごとに承認者を登録し、自己登録は許可しない。
- 承認者には個人単位のアカウントを発行し、事業所IDと対応付ける。共有アカウントは使用しない。
- ログインはメールのマジックリンクまたはパスキーを候補とする。ソーシャルログインだけでは撮影先から与えられた承認権限を示せないため、採用する場合も事前登録済みの承認者との照合に使う。
- 承認時は、事業所ID、承認者ID、対象データのcontent hash、承認日時、表示した承認文言の版、アプリの版を保存する。
- 署名画像は標準要件にしない。販売先が個別署名を求める場合に追加できる設計とする。

## 現在の実装との差分

現行のPCアプリは、事業所IDと対象データのcontent hashを記録し、承認済みデータの保存先へアップロードできる。操作した現場監督者のID、承認日時、承認文言の版を一体の承認記録として保存する機能は未実装である。公開ページを本番へ反映する前に、この証跡を実装して一連のフローを検証する。

PCアプリは事業所ごとに保存先と権限を設定する。署名・公証済みの配布物と公開ダウンロード先を用意するまでは、公開ページから一律にインストーラーを配布せず、撮影開始時に専用リンクを案内する。

## 成功条件

- 公開ナビゲーションが三つの入口に整理されている。
- 現場合意書と撮影参加に関する同意書の役割を説明し、必要な相手には問い合わせに応じて共有できる。
- 未承認データが撮影機材から販売先へ自動提供されないことが明記されている。
- 現在のアプリで記録できる内容と、実装予定の承認者証跡が区別されている。
- 日本語と英語の各ページがモバイルとデスクトップで読める。
