# Task 22: 端末を基準にするPCビューアー

## 目的と成功条件

スマートグラスに残る録画だけを作業一覧の基準にし、その録画だけを指定のDrive保存先と照合する。
未保存の録画は順にプレビューしてアップロードし、正規4ファイルすべての保存先・サイズ・SHA-256の
一致を確認した後に端末から削除する。PCの完了履歴を信用せず、PCを替えても同じ動作にする。
Drive保存後・端末削除前のUSB切断やアプリ終了、削除途中の中断は、次の接続で端末とDriveから再開する。

## 実装

- `core.py`はUSB接続の固定と、未保存録画をプレビュー用にコピーして全4ファイルを照合する責務を持つ。
- `device_sync.py`はまずUSB端末を列挙する。完成録画と削除途中の録画のハッシュだけをDriveへ渡し、
  未保存なら取り込み、保存済みなら端末削除へ進む。コピーや完了履歴だけから一覧を作らない。
- `drive.py`の`current_recordings(content_hashes)`は対象必須。空集合なら通信しない。
  指定事業所の保存先・site・kind・hashで20件ずつ絞り、対象の子4ファイルだけを取得する。
  全ページを読み、不足・重複・移動・削除・不完全な検索結果を保存済みとして返さない。
  最後に録画フォルダと保存先を再確認する。共有ドライブ全体の一覧は取得しない。
- `device_cleanup.py`は、端末にある正規4ファイルの全量SHA-256とサイズを現在のDriveと照合する。
  削除直前にもDriveを確認し、同じ親へ削除待ちフォルダとして移動・syncした後に既知のファイルだけを削除する。
  未完了録画や未知のファイル、リンク、照合不一致は削除しない。
- 削除待ちフォルダ名には、元の録画名・動画のハッシュ・保存先と全4ファイルのID/サイズ/SHA-256の
  マニフェストハッシュを含める。途中で一部ファイルが消えても別PCで再開でき、Driveの内容が変われば停止する。
  PCのjournalは削除判断に使わない。
- 撮影アプリの`metadata.files`が定める正規データは4ファイル。既知の補助ファイル
  (`camera_frames.raw.jsonl`、`sync_report.json`、`content_hash.txt`、`camera_capture_failures.txt`と
  4種の作業用index)は、正規4ファイルの保存を照合した後に端末から削除する。
  補助ファイルをDriveに保存したとみなす実装ではない。
- 接続時のUSB transport IDとserialを削除まで保持し、別端末への接続し直しで削除を続けない。
- 起動時と接続失敗時は一覧を空にする。完了件数の累積表示はなく、未アップロードの録画を表示する。
  Drive保存成功後の削除失敗は「端末の削除待ち」とし、再送を促さず、次の接続で削除を再試行する。
- PCのコピーはプレビュー・転送用、journalは中断送信の再開用。以前に完了したjournalの古いIDは
  再アップロードを妨げない。端末に存在しない録画をPCのコピーから復活させない。

Driveへの照会と端末削除は別システムのため同時に確定できない。削除直前のDrive再確認を境界とし、
以後のDrive側の外部操作まで排除する保証はしない。確認は「接続」時であり、変更の常時監視ではない。

   `stat -c '%s|%d|%i|%y|%z'`を読み取りだけで確認する。未対応なら修正して再ビルドする。
2. 接続前の通常録画名・削除待ち名とDrive照合対象を記録し、導入済み0.4.5の「接続」を実際に押す。
   完了済み20録画は正規4ファイルを照合後に削除する。未完了3録画は削除しない。
3. 削除待ちがなくなったことと、対象20録画のDrive保存が維持されていることを確認する。
   再度「接続」を押し、端末に残った録画だけを処理することと所要時間を確認する。

   SHA-256・ダウンロード内容・親・フォルダの5項目構成を検証する。
