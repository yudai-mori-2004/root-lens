# 26. Codebase hygiene

## 目的

`unit_id`移行後に残った説明と実装の不一致を解消し、データを失う失敗を可視化する。中核処理の責務、複数ランタイム間のマニフェスト契約、依存関係、通常の検証コマンドを、人が追跡できる状態へ整える。

## スコープ

- 現行文書と公開文言を`unit_id`仕様へ統一する。
- Mentraの提出経路とWeb APIの責務を一致させる。
- 録画保存、復元、登録で発生した失敗を握り潰さない。
- 撮影UI、ARKit収録、MCAP生成の責務を分割する。
- source manifestの共通fixtureで各実装の互換性を検証する。
- 認証エラー、アップロード予約、外部依存、lintを整理する。
- Webとモバイルの既知の依存関係脆弱性を解消する。

## 成功条件

- 現行文書と公開ページが現行実装を説明している。
- 対応するデータ経路に未接続の入口がない。
- データを保持すべき失敗が利用者と運用ログから確認できる。
- 複数ランタイムで同じfixtureから同じmanifest digestを得る。
- lint、型検査、テスト、ビルド、依存関係監査が通る。
